# 分析脚本

这里是为了弄清"回环为什么不work"而写的辅助分析脚本，不是 SLAM 主线代码。
每个脚本都可以单独跑，依赖只有 numpy / scipy。

## loop_geometry_stats.py

把 `loops.npz` 里的每个回环对与真值位姿比较，分别算出"PnP 解出的相对位姿"
和"里程计自己估计的相对位姿"相对真值的偏差，并统计基线长度。

结论：145 个回环里，PnP 解出的旋转只有 3 个比里程计更准；旋转误差中位 12.57°，
里程计只有 2.49°。基线中位 0.1189 m，最大 0.3089 m。按基线筛（≥0.15 / 0.20 / 0.25 m）
不能改善旋转精度。

    python loop_geometry_stats.py     # 需要 slam2.py 的 SEQ 指向本机数据目录

## sim_baseline_identifiability.py

受控模拟一。200 个点、两台固定基线的相机，做双视角光束法平差（只优化深度与基线），
加不同水平的像素噪声，看基线能否被恢复。

结论：0.12 m 的短基线也能被恢复到 0.01%（中位）。所以"基线短"本身
不是数值上的病态问题，不能单独用来解释真实数据上 12.57° 的旋转误差。

## sim_rotation_from_depth.py

受控模拟二。基线固定 0.12 m，点坐标固定，只解相对位姿的 6 个自由度，
观察深度噪声对旋转估计的影响。

结论：把深度噪声放大到 50 mm，旋转误差也只有 0.09°。
**这两个模拟都没有复现出真实数据上 12.57° 的旋转误差**，说明真实系统上
还有模拟未覆盖的因素（地图点不严格共享、深度图边缘系统偏差、内点里混有误匹配）。
这个否定的结果同样重要：它避免了给出一个听起来完整但未经验证的因果链。

## sim_rotation_decoupled.py

受控模拟二的另一版：分别扫描第一视角深度噪声与第二视角像素噪声，两种噪声解耦。

## ba_dense_jacobian_memory.py

从真实地图重建 BA 窗口，计算"数值差分稠密 Jacobian"需要多少内存。

结论：40 帧窗口需要 2.9 GiB，200 帧窗口需要 59.7 GiB。
而 BA 的 Jacobian 每行只有 9 个非零元（1 个位姿块 + 1 个点块），
稠密存储的浪费倍数是 参数总数/9，即 967 倍到 4472 倍。
换成手工解析 Jacobian + CSR 稀疏组装后只需 4.7 MB / 20.5 MB。

这就是 `slam2.py` 里必须手工推导 Jacobian 而不用数值差分的原因。
