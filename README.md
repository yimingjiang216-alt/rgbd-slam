# RGB-D 视觉里程计 / 回环检测 / 位姿图优化

RGB-D SLAM 管线,在 TUM FR1 公开数据集上评测。不依赖 g2o / Ceres / GTSAM 等
优化库:李群运算、光束法平差、位姿图优化、回环检测均在项目内自行实现。

用到的数据集:TUM RGB-D Benchmark,`fr1/xyz`(798 帧)与 `fr1/desk`(613 帧)。
数据不随仓库提供,请从 https://cvg.cit.tum.de/data/datasets/rgbd-dataset/download 下载。

---

## 一、做了什么

### 1. 视觉里程计 + 在线局部 BA(`slam2.py`)

前端 ORB 特征匹配 + PnP/RANSAC 位姿估计,维护一个持久稀疏点云地图,
并在跟踪环内做在线局部光束法平差,联合优化位姿与地图点。

| 配置 | ATE RMSE | 相对误差 | 路径长度 |
|---|---|---|---|
| 纯前端 VO | 0.0502 m | 0.63% | 9.479 m |
| + 离线 BA(事后优化) | 0.0510 m | 变差 | — |
| + 在线局部 BA | **0.0449 m** | **0.56%** | 10.961 m |

用 evo 独立验证,与项目内实现的指标完全一致(ATE RMSE 4.4919 cm;旋转 APE RMSE 5.61°,
RPE(δ=1) RMSE 0.64°)。

**关键结论:BA 必须放在跟踪环内(在线),不能做事后优化。**
地图点在建关键帧时用当时的位姿反投影得到,位姿误差被固化进点坐标;
事后 BA 只会把错误几何拟合得更紧——所以离线 BA 反而比纯 VO 更差。

### 2. 回环检测 + SE(3) 位姿图优化(`slam3.py`)

- `loop_detection.py`:ORB 特征、比例测试匹配、PnP/RANSAC、候选搜索、几何一致性校验
- `pose_graph.py`:SO(3)/SE(3) 指数/对数映射、右雅可比、流形 Gauss-Newton + Huber 鲁棒核

**代码经合成数据验证(12 项测试全部通过):**

| 测试 | 项数 | 结果 |
|---|---|---|
| `test_lie.py` | 6 | 指数/对数映射、右雅可比、李代数对数坐标全部通过 |
| `test_pose_graph.py` | 6 | 一致图精确恢复真值(3.9e-16);回环边把残差压到 1.4e-18;固定 gauge 有效;Huber 核能容忍一条错边 |

**在 fr1/xyz 上回环检测工作正常:** 56 个关键帧找到 **145 个**通过验证的回环对,
PnP/RANSAC 内点数常见 100–600,重投影误差中位数 1.1 px。

**位姿图优化器工作正常:**

| | 优化前 | 优化后 |
|---|---|---|
| 回环残差 mean | 0.352 m | **0.037 m** |
| 回环残差 max | 0.687 m | **0.132 m** |

## 二、没做成的部分(这部分是重点)

**加入回环后,ATE 没有变好,反而变差了。** 这是一个阴性结果,原因已定位。

### fr1/xyz:回环基线只有 12 cm,旋转不可观测

| 方法 | ATE (RMSE) | 旋转中位误差 |
|---|---|---|
| 纯 VO | 0.0450 m | 2.24° |
| VO + 在线局部 BA | 0.0449 m | 2.24° |
| + 回环 + 位姿图 | **0.1975 m** | **17.22°** |

(以上为 eval_v3.json 实测值,经 eval_v3_rerun.json 复跑逐位一致。真值路径长度 8.01 m。ATE 用去重心 + 只做刚体旋转对齐,不做相似变换,避免尺度把误差藏起来。)

排查过程:

1. **回环测量本身看着是亚像素精度的。** PnP 解的重投影误差中位数 1.1 px,
   86% 的点误差 < 3 px。求解器没问题。
2. **但回环的相对旋转是错的。** 拿 145 个回环边跟真值比:

   | | 相对旋转误差 | 相对平移误差 |
   |---|---|---|
   | PnP 回环测量 | **12.58°** | 0.261 m |
   | 里程计估计 | **2.59°** | 0.066 m |

   145 个回环里只有 3 个的旋转比里程计更准。
3. **根因是基线太短。** 这些回环对的真实基线中位数只有 **0.119 m**。
   基线 12 cm 时,旋转基本不由 PnP 的几何决定,而由深度噪声决定——
   所以重投影看起来很完美(1 px),旋转却错了 12°。这是典型的**旋转不可观测**。
4. **筛基线无效(实测)。** 这些回环对最大基线只有 0.309 m,
   把门槛提高旋转误差不变(13.3°)。不是"某些对太短",而是这个序列里所有候选对都短。

### fr1/desk:回环在候选阶段就几乎全失败(视点变化,ORB 描述子过不了)

换 desk 是为了解决"基线太短"。但撞上第二个更硬的障碍:

**先修正一处说法。** 原先这里写"desk 的重访基线中位数 0.487 m(xyz 只有 0.119 m),
基线够了、但视角变了导致匹配失败"。本次在原机复跑核查发现:
desk 上**通过验证的那 1 个回环对,真实基线只有 0.0954 m**,比 xyz 的 0.1189 m 还短。
也就是说 desk 上**根本没建立起基线足够长的回环约束**——ORB 在候选阶段就匹配失败了。

(0.487 m 统计的是"所有可能的候选重访对",不是"通过验证的回环对"。按真值独立重算,
 候选重访基线中位 0.36-0.37 m、重访时相机相对旋转中位 20-23 度、上四分位 37-59 度,
 与原文量级接近;但当初那次统计没有留下脚本,无法确认其候选筛选窗口,故以本次实测为准。)

- VO 本身能跑:108 个关键帧,241878 个地图点,纯 VO ATE 0.0751 m(旋转中位误差 6.72°,是 xyz 的 2.24° 的三倍)。
- **回环检测几乎全失败:603 个候选对,只通过 1 个。**

  | 淘汰阶段 | 数量 |
  |---|---|
  | 匹配点 < 25 | 148 |
  | 3D 点 < 25 | 26 |
  | PnP 失败 | 20 |
  | PnP 内点 < 25 | 216 |
  | 几何不一致 | 192 |
  | **通过** | **1** |

- **加特征数无效(实测)。** `nfeatures` = 2000 / 4000 / 8000,匹配数恒为 15。
  问题不在特征点够不够,而在描述子本身对不上。
- **根因是视角变了。** desk 是拿着相机绕桌子走,回访时相机朝向已经不一样。
  两视角相对旋转中位数 **25.5°**(p25=18.8°, p75=32.2°, max=45°)。
  ORB 是**旋转**不变的,但不是**视点**不变的,视点一变描述子就对不上。

### 两个序列失败方式完全不同

- **xyz**:回环找到了(145 个),但真实基线只有 12 cm,测量里的旋转信息不可靠。
  优化器很忠实地把 145 条这样的边都满足了(残差 0.352 → 0.037),代价是把位姿拉离真值。
- **desk**:回环在候选阶段就几乎全失败(视点变化导致 ORB 描述子匹配不上),
  因此没能建立起基线足够长的回环约束。
- 两者都不是优化器 bug,也不是检测器 bug,而是**回环约束这个测量在这两个序列上不可用**。

---

## 三、结论边界

- 可以说的:实现了回环检测与 SE(3) 位姿图优化,代码经 12 项合成数据测试验证,
  在真实序列上找到 145 个回环并把回环残差从 0.352 m 降到 0.037 m。
- **不能**说"回环让轨迹精度提升了"——实测是变差的,原因已定位。
- 要真正做成,缺的是:**在 BA 里联合优化地图点**(而不是用一张已固化的点云去做 PnP),
  以及**换成视点不变的描述子**(SuperPoint+SuperGlue / NetVLAD 这类)。

## 五、复现

```
# 视觉里程计 + 在线局部 BA
python slam2.py all

# 回环检测 + 位姿图优化
python slam3.py detect
python slam3.py graph
python slam3.py eval
python slam3.py            # 三步全跑

# 单元测试
python test_lie.py
python test_pose_graph.py
```

数据放到 `data/rgbd_dataset_freiburg1_xyz/` 与 `data/rgbd_dataset_freiburg1_desk/`,
目录结构按 TUM 官方压缩包解压后的样子即可(rgb.txt / depth.txt / groundtruth.txt + rgb/ + depth/)。
相机内参 fx=517.3 fy=516.5 cx=318.6 cy=255.3,深度值 / 5000 = 米。

## 六、环境

Python 3.14,numpy / opencv-python / scipy / matplotlib。

## 七、一个测量上的提醒

fr1/xyz 的真值轨迹只在一个 0.41 m 的小框里打转(总路程 8.01 m)。
也就是说相机在原地绕小圈,轨迹几乎是自己叠在一起的。两个后果:

1. 这个序列上"回环"和"短基线重访"是一回事,几乎没有长基线的真回环,
   它天生测不出回环模块的价值。
2. 在这个序列上报 ATE 要小心:一条几乎原地打转的轨迹,即使形状完全不对,
   只要整体尺度接近,位置误差也不会很大。所以更该同时看路径长度比
   (估计 11.36 m vs 真值 8.01 m,高出约 42%)和旋转误差。
